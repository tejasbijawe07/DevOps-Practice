## Secrets, Artifacts & Running Real Tests in CI

- storing sensitive values securely, saving build outputs, and running actual tests.
- In CI/CD (GitHub Actions, Jenkins etc.), an artifact is a file or collection of files that a workflow produces and saves after a job finishes.
- These files can then be downloaded, shared with other jobs, or kept for future reference.
- In CI:
     - Source code → Input
     - Build/Test process → CI pipeline
     - Artifact → Output (application, report, logs, etc.)
- Examples of Artifacts:
 
| Workflow Step      | Artifact Produced                                                      |
| ------------------ | ---------------------------------------------------------------------- |
| Compile Java       | `.jar` file                                                            |
| Build React app    | `build/` folder                                                        |
| Build Docker image | Image (usually pushed to a registry rather than stored as an artifact) |
| Run tests          | Test reports (JUnit XML, HTML)                                         |
| Code coverage      | Coverage reports                                                       |
| Packaging          | ZIP/TAR files                                                          |
| Mobile app         | `.apk` or `.ipa`                                                       |

- Why are Artifacts useful?
    - Download Build Output:
        - Instead of rebuilding the project, you can download the already-built files.
    - Share Files Between Jobs.
    - Debug Failures:
        - If tests fail, we can save:
        - Logs
        - Screenshots
        - Core dumps
        - HTML report
    - An artifact is the output generated by a CI/CD pipeline—such as compiled binaries, test reports, logs, or packaged applications—that is stored so it can be downloaded, shared between jobs, or used in later stages like testing or deployment.

### Task 1: GitHub Secrets
- Go to your repo → Settings → Secrets and Variables → Actions
- Create a secret called `MY_SECRET_MESSAGE`
- Create a workflow that reads it and prints: The secret is set: true (never print the actual value)
- Try to print `${{ secrets.MY_SECRET_MESSAGE }}` directly — what does GitHub show?
- Write in your notes: Why should you never print secrets in CI logs?


#### 1. Create Github Secret:

- GitHub → Your Repository → Settings → Secrets and variables → Actions → New repository secret

- Create:

       Name:
       MY_SECRET_MESSAGE

       Secret:
       Hello this is my secret


#### 2. Workflow file- secrets-demo.yml:


    name: Secrets Demo

    on:
      push:
        paths:
          - ".github/workflows/secrets-demo.yml"

    jobs:
      secret-check:
        runs-on: ubuntu-latest

        steps:
          - name: Check if secret is set
            run: |
              if [ -n "${{ secrets.MY_SECRET_MESSAGE }}" ]; then
                 echo "The secret is set: true"
              else
                 echo "The secret is set: false"
              fi
